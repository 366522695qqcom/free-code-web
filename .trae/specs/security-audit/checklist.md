# Security Audit Checklist

## 架构梳理
- [ ] 所有 HTTP Route Handler 入口点已识别并分类（认证/公开）
- [ ] 认证中间件白名单与实际路由一致
- [ ] CLI/SDK 入口点已识别
- [ ] WebSocket/直连入口点已识别
- [ ] 信任边界图已输出（公开 / 认证 / 内部 / 沙箱）

## 认证与访问控制
- [ ] JWT 生成使用足够强度的密钥，密钥未硬编码在源码中
- [ ] JWT 验证逻辑正确（签名、过期、签发者校验）
- [ ] 登录接口有速率限制或暴力破解防护
- [ ] 会话无固定（fixation）漏洞（登录后重新生成 token）
- [ ] 所有非白名单 API 路由均被 middleware 保护
- [ ] 权限系统无绕过路径（直接调用内部 API、参数篡改）
- [ ] CLI 端认证凭证安全存储

## 注入向量
- [ ] 所有 SQL 查询使用参数化（无字符串拼接用户输入）
- [ ] Shell 命令构造使用参数数组而非字符串拼接
- [ ] 文件路径操作已防路径遍历（resolve + 前缀校验）
- [ ] URL 构造不使用用户输入直接拼接
- [ ] 无模板注入风险（无用户输入直接进入模板引擎）

## 外部交互
- [ ] LLM API 请求的目标 URL 来自配置，非用户可控
- [ ] Web Fetch/搜索工具的 URL 经过 SSRF 防护（内网地址过滤）
- [ ] MCP 服务器连接需用户明确批准
- [ ] Sandbox API 调用使用服务端 Token，不暴露给客户端
- [ ] 出站请求使用超时和合理的重试策略

## 敏感数据处理
- [ ] 源码中无硬编码的 API Key、密码或 Token
- [ ] `.env.example` 中无真实凭证
- [ ] 认证密钥在数据库中加密或哈希存储
- [ ] 日志输出无 API Key、Token、密码或 PII
- [ ] 聊天请求中的 API Key 不在日志/错误消息中泄露
- [ ] CLI 配置文件无明文存储敏感凭证

## 报告完整性
- [ ] 每个发现包含：攻击者画像、可控输入、代码路径、影响、修复建议
- [ ] 发现按严重度（Critical / High / Medium）分组
- [ ] 无 Medium+ 发现时输出清洁审计声明
